# 青少年攀岩系列賽 — 比賽網站與賽事系統規劃

> 版本：v0.1（草案）｜搭配《比賽規劃》使用

## 1. 系統範圍

一套系統，五種使用介面：

| 介面 | 使用者 | 裝置 | 用途 |
|---|---|---|---|
| ① 公開網站 | 家長、選手、教練 | 手機／電腦 | 賽事資訊、報名繳費、名單、即時成績 |
| ② 排隊 Kiosk | 選手 | 比賽 iPad | 感應 → 選路線 → 取號 |
| ③ 叫號／成績螢幕 | 現場觀眾 | 電視 | 叫號、即時排行榜 |
| ④ 裁判端 | 路線裁判 | 裁判手機 | 看叫號、判完攀／未完攀 |
| ⑤ 管理後台 | 主辦單位 | 電腦 | 場次、組別、路線、報名、成績、頒獎 |

## 2. 公開網站（①）

### 頁面
- **首頁**：系列賽介紹、四場日期地點、報名按鈕、最新公告
- **賽事資訊**：每場的場地、交通、流程表、規則、組別說明
- **報名**：
  - 選擇「單場 1,500」或「四場套票 5,000」
  - 填寫選手資料 → 系統依 **年級自動分組**
  - 勾選免責聲明＋家長同意書（未成年必填）
  - 線上付款
- **我的報名**：以手機號碼＋驗證碼登入，查看報名、付款狀態、組別、號碼、成績
- **選手名單**：各場各組名單（只顯示姓名、學校，可遮蔽部分姓名，如「王○明」）
- **即時成績**：比賽中自動更新的各組排行榜
- **歷屆成績／系列賽總排名**
- **公告、FAQ、聯絡我們**

### 報名欄位
| 欄位 | 必填 | 備註 |
|---|---|---|
| 選手姓名、性別、生日 | ✔ | 性別用於 >20 人拆組 |
| 就讀學校、年級 | ✔ | 自動分組依據 |
| 身分證字號 | ✔ | 投保用，**加密儲存**，賽後刪除 |
| 監護人姓名、手機、Email | ✔ | 通知與登入用 |
| 緊急聯絡人 | ✔ | |
| 所屬隊伍／教練 | | 方便教練查詢團隊成績 |
| T 恤尺寸 | | 若有紀念衫 |

### 付款
- 建議串接 **綠界 ECPay** 或 **藍新 NewebPay**（信用卡、ATM 虛擬帳號、超商代碼）。
- 備案：銀行轉帳＋填寫末五碼，後台人工對帳。
- 套票 5,000 一次付清，自動報名四場。
- 付款逾時（如 3 天）自動取消名額。

### 組別人數與拆組
- 後台即時顯示各組男／女人數。
- 報名截止時，某組單一性別 > 20 人 → 系統提示拆組 → 管理員確認後鎖定並公告。

## 3. 排隊 Kiosk（②，比賽 iPad）

**流程**
1. 選手感應手環／掃號碼布
2. 螢幕顯示：姓名、組別、目前分數、**本組可挑戰路線**（已完攀的灰掉、各路線目前排隊人數）
3. 點選路線 → 顯示「你是第 N 位，前面還有 X 人」
4. 若已在其他路線排隊 → 提示「請先完成或取消目前排隊」

**規則由系統強制**
- 同時只能排 1 條路線
- 已完攀路線不可再排
- 只能選本組路線（共線路線兩組都看得到）
- 非該梯次時間不能排隊

**iPad 設定**：Safari 加入主畫面（PWA 全螢幕）＋「引導使用模式」鎖定 App，避免選手亂按跳出。

## 4. 叫號／成績螢幕（③）
- 叫號畫面：每條路線顯示「上場中 #12 王小明」「準備 #15」「排隊 4 人」
- 排行榜畫面：依組別輪播，每 10 秒切換
- 比賽倒數計時

## 5. 感應方式（重要技術限制）

**iPad 沒有可供 App／網頁讀取的 NFC 晶片**，Safari 也不支援 Web NFC，所以「感應 iPad」需選以下其一：

| 方案 | 做法 | 成本 | 建議 |
|---|---|---|---|
| A. 外接 RFID 讀卡機 | USB-C「鍵盤模擬」讀卡機接 iPad，選手戴 RFID 手環，感應後卡號直接輸入網頁 | 讀卡機約 NT$500–1,000/台；手環約 NT$15–30/個 | ⭐ **推薦**，最像「感應」、速度快，網頁就能用 |
| B. QR Code | 號碼布印 QR Code，iPad 前鏡頭掃描 | 幾乎 0 | 備援方案，速度較慢、光線影響大 |
| C. 輸入號碼 | 數字鍵盤輸入選手號碼＋生日末 4 碼 | 0 | 最後備援 |

建議 **A 為主、B／C 為備援**，三者系統都支援。手環四場共用，報名套票者發一次即可。

## 6. 裁判端（④，裁判手機）
- 裁判以帳號登入，選擇負責路線（可負責 1–2 條）
- 畫面：
  - 目前上場選手（姓名、號碼、照片可選）＋本次嘗試計時
  - 大按鈕：**✅ 完攀**／**❌ 未完攀**／**⏭ 未到場**（可選：🟡 Zone）
  - 下一位選手預覽
- 按下後自動叫下一位；**5 秒內可復原**（防誤觸）
- 修改已送出的成績需總裁判權限，並留紀錄（誰、何時、改了什麼）
- 斷線時先存在手機，恢復連線後自動上傳

## 7. 管理後台（⑤）
- **場次設定**：日期、場地、梯次時間、報名期間、費用
- **組別設定**：年級範圍、性別拆組門檻（預設 20）、梯次分配
- **路線設定**：路線編號、分數、所屬組別（多選，處理共線）、牆區／對應 iPad
- **報名管理**：名單、付款狀態、對帳、退費、轉讓、匯出保險名冊
- **報到**：掃報名 QR → 綁定 RFID 手環 → 完成報到
- **裁判管理**：帳號、路線指派
- **賽中監控**：各路線排隊長度、裁判在線狀態、異常提醒
- **成績**：即時排名、同分處理、申訴修改、**頒獎名單（各組前 2 名）一鍵產出**、獎狀列印、匯出 Excel
- **系列賽總積分**

## 8. 資料結構（主要資料表）

```
Season 系列賽
 └─ Event 場次（A22 / 明德 / 大埔 / A22 正式賽）
     ├─ Wave 梯次（A / B）
     ├─ Division 組別（G1–G5，可拆 男/女）
     ├─ Route 路線（編號、分數、牆區）
     │    └─ RouteDivision 路線↔組別（多對多，處理共線）
     ├─ Registration 報名（選手、組別、號碼、付款狀態）
     ├─ QueueEntry 排隊（選手、路線、狀態：排隊/上場/完成/棄權）
     └─ Attempt 嘗試（選手、路線、裁判、結果、時間）
Athlete 選手（基本資料、RFID 卡號）
Guardian 監護人
Order / Payment 訂單（單場或套票）
User 帳號（管理員 / 總裁判 / 裁判）
AuditLog 修改紀錄
```

成績不另外存，一律由 `Attempt` 即時計算，避免資料不一致。

## 9. 技術架構建議

| 項目 | 建議 | 理由 |
|---|---|---|
| 前端 | Next.js（React）＋ PWA | 一套程式涵蓋網站、iPad、手機、螢幕 |
| 後端／資料庫 | Supabase（PostgreSQL＋登入＋即時同步） | 排隊與成績需即時推播，免自架伺服器 |
| 部署 | Vercel | 免費額度足夠，部署簡單 |
| 金流 | 綠界 ECPay 或藍新 | 台灣常用、支援 ATM／超商 |
| 通知 | Email＋簡訊（或 LINE 官方帳號） | 報名成功、繳費提醒、賽前通知 |

預估月費：比賽期間約 NT$0–1,500（主要是簡訊與金流手續費）。

**現場網路備援**：iPad 與裁判手機連 4G/5G 分享器；系統斷線時仍可在本機暫存、恢復後同步；保留紙本記分表。

## 10. 個資與安全
- 選手多為未成年：報名需監護人同意；公開頁面姓名部分遮蔽。
- 身分證字號加密儲存，只有管理員可匯出保險名冊，系列賽結束後刪除。
- 後台帳號分權限：管理員／總裁判／裁判，裁判只能看自己路線。
- 網站需有隱私權政策頁。

## 11. 開發時程（以第一場比賽日為 D 日）

| 階段 | 時間 | 內容 |
|---|---|---|
| 1. 報名系統 | D−8 週 ～ D−5 週 | 公開網站、報名、金流、後台報名管理 → **D−5 週開放報名** |
| 2. 賽事系統 | D−5 週 ～ D−2 週 | 路線設定、報到、Kiosk、裁判端、叫號螢幕、即時成績 |
| 3. 實地測試 | D−2 週 ～ D−1 週 | 在 A22 找 20–30 人模擬大亂鬥，測網路、讀卡機、流程 |
| 4. 第一場上線 | D | 賽後檢討修正 |
| 5. 正式賽模組 | 第三場前 | 資格賽／決賽輪轉、Top/Zone 計分、系列賽總排名 |
